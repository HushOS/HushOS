# Privacy answers: Apple App Privacy and Google Data safety

Item by item, with the reason from the code. Checked against the code on branch `redesign/alpine` and the store rules on 2026-10-05.

**Confirm with counsel before submitting.** Two answers are judgement calls the rules don't settle: whether end-to-end encrypted file contents count as "collected" for Apple (Google says outright that they don't), and whether a report makes contents collectable. The recommended answers below are the conservative reading of what the server can actually read.

## Apple: App Privacy (App Store Connect > HushOS > App Privacy)

Definitions (https://developer.apple.com/app-store/app-privacy-details/, checked 2026-10-05): data is "collected" when it is sent off the phone in a way that lets the developer access it for longer than it takes to serve the request; data processed only on the phone is not collected. "Tracking" means combining with other companies' data for advertising, or sharing with data brokers. Apple's page has **no explicit carve-out for end-to-end encrypted data**.

**Do you or your third-party partners collect data from this app?** Yes.

### Privacy manifest (`PrivacyInfo.xcprivacy`)

Since 1 May 2024 Apple refuses uploads that use a "required reason" API without declaring it (https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api, checked 2026-10-05). Each bundle with its own executable needs its own file. The code uses:

- **UserDefaults**: the app (`AppModel.lastEmail`, `@AppStorage` sort and recent searches, `BackgroundAccess`) and `HushOSKit/Offline.swift` (`UserDefaults(suiteName: group)`), which every extension links. Reasons `CA92.1` (app only) and `1C8F.1` (app group).
- **File timestamps**: `HushOSKit/Vault+Writes.swift` reads `.modificationDate` of the file being uploaded; `ShareHandoff.swift` reads `contentModificationDateKey` in the app group; the File Provider handles `creationDate`/`contentModificationDate`. Reasons `C617.1` (files in the app or app group container) and `3B52.1` (files the person chose).
- No disk-space, boot-time or keyboard APIs were found.

It is `apps/ios/Privacy/PrivacyInfo.xcprivacy`, in the resources of all five targets (`App`, `Files`, `FilesUI`, `Share`, `Widgets`, all linking HushOSKit). Check the archive (`Products/Applications/HushOS.app/PrivacyInfo.xcprivacy` and each `PlugIns/*.appex/PrivacyInfo.xcprivacy`). Its contents:


`NSPrivacyCollectedDataTypes` is left empty because the App Privacy answers above are what the App Store shows; filling it in to match is optional for an app (it is required of third-party SDKs).

## Google: Data safety (Play Console > Policy > App content > Data safety)

Definitions (https://support.google.com/googleplay/android-developer/answer/10787469, checked 2026-10-05): "collection" is sending data off the device; "sharing" is transferring it to a third party (service providers and user-initiated transfers excluded). Google is explicit about encryption: data "unreadable by you or anyone other than the sender and recipient as a result of end-to-end encryption does not need to be disclosed."

## When to revisit these answers

- Any analytics, crash reporting or push notifications in the apps.
- In-app sign-up (both stores' account-deletion rules then apply in full).
- Anything sent to the server unsealed that is now sealed, or vice versa.
- A support form or chat inside the app (Customer Support for Apple; App activity / Messages for Google).
